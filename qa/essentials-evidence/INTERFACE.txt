1) EvidenceRef.TryParseRecordRef(string? rf, out Guid recordId, out string itemId, out string error) -> bool
   File: server/SimCEO.Api/Work/Evidence.cs (public, static).
   Contract: bare "<guid>" = legacy whole-record ref (itemId ""); "<guid>:<itemId>" =
   explicit item ref where itemId must be NONEMPTY and canonical (no leading/trailing
   whitespace). Split is on the FIRST colon so item ids containing colons round-trip
   with ForRecordItem. Anything else (blank, "A:", "A: ", "<guid>:", "<guid>: ", ":s1",
   non-GUID parts) returns false and must NEVER fall back to whole-record.
   Wire parsing (EvidenceRef.Parse) stays lenient by design; strictness is enforced by
   actual consumers. Source/caller compatibility: old bare-GUID refs keep working
   everywhere; callers that built composites by string concat now route through this.

2) RecordsOps.ValidateRestoreEntries(IEnumerable<RecordDraft> drafts, IDictionary<string,int>? sourceOriginalOf = null, IDictionary<string,int>? sourceCanonicalOf = null) -> string? (null = valid)
   File: server/SimCEO.Api/Work/RecordEndpoints.cs (public, static).
   The ONE shared complete staged record validator, called by Ops BEFORE any destructive
   replacement (BackupGraphValidator.Validate). Covers: lineage IDs + uniqueness; typed
   items (ItemMap/ValidateDraftItems, rejects numeric ids); Approved/Discarded strict
   string lists + membership + disjointness; typed history (StrictHistoryEntries: seq
   ascent, integral counters, REVISION MONOTONIC non-decreasing, non-empty actor/token)
   + final revision/token tip match (HistoryTipMatches) + actor/item-action correspondence
   (HistoryActionCheck: approve->approved, discard->discarded, revise->items, branch/create
   carry none); supersedes strict string GUIDs + parent existence in the SAME batch +
   same board/meeting scope + batch-local cycle detection (A->B->A); snapshot shape
   (StrictSnapshotEntries) + SnapshotRestoreCheck (item exists, declared-ref correspondence,
   one entry per item/ref/version, no same-target different versions, duplicate/undeclared/
   unapproved/null-capture rejection, available entries carry bytes); MODERN writer-identity
   correspondence: Version>=1, content hash == Hashing.HashOf(ItemsJson), status/decided
   lifecycle == writer RefreshDecided semantics (superseded requires Decided; empty sets
   allow open/undecided or discarded/undecided; otherwise Status==ComputeStatus and
   Decided==(no pending && any decision)); status/state coherence (known statuses, no
   empty decisions).
    Legacy rule (narrow persisted provenance, F2/P1): ONLY a persisted LegacyReview=true marker
    with blank history AND blank snapshots on a never-mutated row (ReviewRevision<=1) counts as
    genuine pre-review data (e.g. the primary 20261103-1021 backup drafts with no
    DiscardedJson/ReviewToken/HistoryJson/EvidenceSnapshotJson/LegacyReview keys: controlled
    old-schema import (backup version<4) and PG boot backfill set missing markers true ONLY
    where the recognized shape AND the genuine base contract validate). Revision<=1 alone
    is NOT proof of legacy: modern new no-ref rev1 rows are naturally blank, and marker-
    false/null blank rows stay on the modern path and fail closed. Accepted legacy rows are
    base-validated (typed items/decisions, version, hash, known status; lifecycle coherence
    is pre-modern and not required) and stay inert readonly: no approval history is
    fabricated, no captures exist, mutations stay closed except narrow explicit legacy
    adoption through the existing refresh/revise workflows (first history entry written
    explicitly; approve/discard stay closed; decided legacy rows stay terminal).
   sourceOriginalOf maps source-id -> ORIGINAL (pre-renumber) version; sourceCanonicalOf
   maps source-id -> CANONICAL version (staged head pin, else staged family max). Ops builds
   both from the staged backup''s own sources+migrate-version events+heads via
   BuildSourceVersionMaps (never caller-invented).

3) RecordsOps shared helpers (public, static, same file)
   - HistoryTipMatches(RecordDraft d, out string error): final history entry revision/token
     equals the row''s ReviewRevision/ReviewToken. Used by StrictStateCheck AND the restore validator.
   - HistoryActionCheck(...map, approved, discarded...): per-action item correspondence.
   - SnapshotRestoreCheck(map, approved, snaps, sourceOriginalOf, sourceCanonicalOf, out error):
     restore-time snapshot correspondence (stricter than live reads). Pinned declarations must
     equal the entry version OR a genuine validated alias of that source''s actual mapping:
     declared pin == ORIGINAL and captured version == CANONICAL with canon>=orig>=1
     (requested1/resolved3 valid, requested1/captured999 and null/wrong/duplicates reject).
   - BuildSourceVersionMaps(sources, events, heads) -> (OriginalOf, CanonicalOf): the single
     staged-map construction contract. Original = min migrate-version from-version per source
     (fallback: staged current version, never an alias); canonical = staged head pin (HeadVersion>0)
     else staged family max. Used by OpsEndpoints.BackupGraphValidator AND QA.
   - RefScalarValid(JsonElement ref, out string error): singular typed gate for ONE ref object
     (string kind/ref/id/url/title/excerpt/sectionId/location/contentHash-or-null; version
     null-or-positive-integer; indexGeneration null-or-integer). RefScalarsValid is the array
     wrapper. ValidateDraftItems applies the singular gate at WRITE time, so publication and
     reads enforce identical shapes.
   - RefScalarsValid(JsonElement refs, out string error): shared ref/scalar gate used by BOTH
     BuildExport modes, IsReadableItems, and the write validator. Non-array refs, non-object
     entries, non-string scalars, and non-positive-integer versions fail the whole export closed
     with no failopen partial render. Stored bytes are never erased.

5) RecordsOps live/stored record resolution (public behavior, same file)
   - ResolveEvidenceAuthorized: explicit item refs resolve the REFERENCED item with non-empty
     text; LIVE Current requires the effective referenced owner (EffectiveChains over the
     REFERENCED record''s scope) to be (referencedRecordId, referencedVersion). A replaced
     historical item (A:s1 BUY superseded by B:s1 CUT) is NOT live-current. Whole-record cards
     additionally require approval-to-item correspondence (every approved id names a draft item;
     ghost approvals are unavailable) plus non-empty export text (empty/invalid approved content
     never yields available). Malformed composites are unavailable, never whole-record.
   - MergeEvidenceForRead: stored snapshots show historical bytes with CurrentEligible=false
     when the owner moved (readable but noncurrent); readback covers declared refs by the
     version-less target identity, so requested1 reads back EXACTLY ONE available canonical3
     card instead of appending an unavailable duplicate. Unversioned v1 one-card preserved.
   - BuildExport(itemsJson, approvedJson, detailed): both modes validate EVERY item
     (approved or not) before any render; every approved id must name a draft item (ghost
     fails closed); at least one approved item must carry non-empty text (empty-approved-text
     records yield ""); detailed mode fails closed on any unparseable declared ref (no silent
     omit). Invalid content becomes controlled "" (unavailable/error downstream), never an
     empty available card, without erasing stored bytes.
   - IsReadableItems: strict object shape + string id/text + string optional detail/status/scope
     + shared ref/scalar gate per item.

     Malformed composite -> "record ref malformed".

   section untouched.

7) SourceGovernance family floor provenance (P1 sparse) + code-only callback seam
   - SourceFamilyHead.FloorVersion (persisted, default 0): first-known legitimate version of
     the family. Recorded truthfully on live data at head/stub creation (min present version),
     backfilled (min present) for pre-provenance heads/stubs at upgrade (startup MigrateStore /
     restore migration; never raises an established floor, never invents history). Carried in
     backups (v4, additive: old readers ignore it, old exports deserialize to 0 = strict).
   - Pending-only sparse families (e.g. genuine single-v3 legacy migrations) carry the floor in
     an exported allocation STUB head (HeadVersion 0, empty identity, HighWater = family max):
     stubs never satisfy headship, are skipped by head-coverage validation, and fold into real
     heads on promotion. Backup tampering (a member deleted post-export) still rejects because
     the stub retains the pre-deletion floor.
   - Restore dense rule is floor-aware: every version in floor..max must be present (floor 0/
     unknown = strict dense-from-1). Missing versions reject ("snapshot family skips version vN;
     partial-family removal is not supported"). Head floor <0 rejects; floor above a positive
     head pin rejects; floor above family max rejects.
   - SourceGovernance.FinishIndexCallbackFault (public static Func<bool>?, code-only seam):
     QA-only inner-callback fault fired AFTER staged section/head/event writes inside the ACTUAL
     FinishIndex unit callback: the fault escapes (no inner catch) so Atomic rolls back ALL
     staged effects. Never HTTP/env/header. A predecessor inner-catch that swallowed this fault
     would commit partials and fail the rollback assertions (proven by the QA negative control).

8) OpsEndpoints change (record-validation loop/data ONLY)
   BackupGraphValidator.Validate: the legacy per-draft inline loop (which demanded SupersedesJson
   OBJECTS while healthy amend writes STRING ids) is REPLACED by the single call
   RecordsOps.ValidateRestoreEntries(r.drafts, sourceOriginals, sourceCanonicals), with both maps
    built by RecordsOps.BuildSourceVersionMaps(r.sources, r.events, r.heads). Capture/restore
    authority, spend, auth, jobs/voice, wiki, blobs, images untouched. Controlled old-schema
    legacy-marker import runs immediately before: ApplyLegacyMarkerBackfill(r.drafts, r.version)
    upgrades missing (null) markers to true ONLY for pre-marker backups (version<4) where the
    recognized prehistory shape and genuine base contract validate; v4 wiped rows keep
    null/false and fail closed. Just-marked rows with a blank token receive the deterministic
    boot-style legacy token so the existing refresh/revise token match stays usable; nothing else
    is rewritten. Refresh and revise/amend-branch admit pending genuine-legacy
    rows via IsLegacyAdoptable (first history entry written explicitly); all approve/discard
    paths keep the strict gate.
