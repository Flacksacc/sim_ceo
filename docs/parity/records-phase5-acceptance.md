# Records Phase 5 one-document review - acceptance contract

Scope: Phase 5 gaps only. One-document review with working notes, per-item approve, revise, set aside, approve selected and approve all, amendment of final approved records, evidence excerpts, recent input, version and watermark context, predecessor and successor navigation, effective line.
Human readable throughout: no raw identifiers, no JSON, no hashes, no tokens on screen. Decision ordinals label every control.

## Source changes

Backend: narrow authorized effective projection added (effectiveHeadId/effectiveHeadVersion on both review payloads from actual EffectiveChains/mine, never inferred from successors); all CAS, hash, token, watermark, permission, supersession, staged atomic, provisional-note-ineligible, and evidence-snapshot protections are preserved as traced. No storage/authority/approval semantics changed.
Frontend (web/src/App.tsx, web/src/human-format.ts):
- Amendment has its own eligibility predicate: only a final approved (decided + approved status, not superseded) record with a manage grant can amend under its own CAS guards. Open or partially decided drafts cannot amend; per-item and whole-draft revise stay gated on the actionable pending-review predicate.
- The whole-document editor resets owner, typed revision, and base authority together on any board/meeting/record switch, hydrates pristine text from the authoritative review snapshot (same bytes as the submitted guards), preserves owner typing, and refuses to submit stale typed text with fresh guards: the base revision/hash is retained and an explicit reload-or-retype reconcile is required. Explicit Reload performs a fresh authorized review GET under the captured canonical identity/epoch/token/visit/record and applies fresh rows with all metadata/refs/base guards only if still owned with no newer typing (otherwise preserves edits; 401/403 never reset or falsely succeed); it then bumps a scoped editor generation (key + resetGen) that remounts/resets ALL child fields/refs/detail/metadata to the current review, stays visible after reviewError for both open revise and final amend editors, and never reposts old rows via onChange after reload; edited text AND detail both dirty the revision.
- Partially approved authoritative heads render as current for both manager and guest (pending no longer forces historical). Historical approved text is distinct from the authoritative effective head (actual server effective headId/headVersion, never successors.length; guests redacted successors stay historical via draft.effective.headId, managers via narrow effectiveHeadId; approved ancestor with pending child stays current, obsolete guest v1 stays historical): decided heads render a single current-record card from the full effective set (inherited + replaced with approving versions, never hist-first); non-head versions render a historical card plus a current-effective-record card (lineage effects with from/to versions for managers, inherited approved items with approving versions for guests). No "no pending" claim is ever derived from the redacted guest pending list; guest watermarks render honestly as unknown when the guest DTO carries no watermark.
- All selection controls (checkboxes, approve selected, approve all) require manage plus the server valid pending nonterminal review; the pending surface itself renders only for actionable reviews, so superseded, decided, and invalid reviews expose zero approval, revise, discard, and selection controls.
- Human projections cover note/evidence JSON objects AND arrays through a per-field allowlist with scrubbed identifiers including n- prefixed ids, title-only objects, nested JSON-encoded strings projected boundedly, humanized paragraph labels (never raw camel), truncated 600-char dossier/message/note excerpts extracted tolerantly (never raw braces/keys), and a safe neutral fallback for unsupported shapes. JSON string layers decode boundedly (max 3); quoted, extra-encoded, unknown-protocol, and truncated layers fail human-safe while ordinary prose (including quoted prose) stays intact. Wire and snapshot bytes are unchanged. Omitted-packet manifests keep a human omission warning instead of vanishing. Note titles are projected, not verbatim.
- Wire and snapshot bytes are preserved. No effective export dump and no lineage origin field use. Version links resolve through singular authorized record detail with parent checks, so navigation works beyond the newest fifty list window. Reviewed and current meeting watermarks render separately with a stale indicator. Newer version wording claims existence only, never effective replacement, unless authority proves it.
